# 書き出し・点検・トラブルシューティング

## PDF / EPUB の書き出し

### プレビューから

プレビュー上部の **PDF** または **EPUB** を押すと、表示中のノート・フォルダ・目次ノートがそのまま書き出し対象になります。

### コマンドから

| コマンド | 対象 |
|---|---|
| **Vivlio: PDF に書き出す** | アクティブな Markdown ノート |
| **Vivlio: EPUB に書き出す** | アクティブな Markdown ノート |
| **Vivlio: このフォルダを本として書き出す** | アクティブノートの親フォルダ |

フォルダを右クリックして **Vivlio: 本として書き出す**こともできます。

## 書き出しダイアログ

| 項目 | 説明 |
|---|---|
| **形式** | PDF / EPUB。変更すると拡張子も切り替わります。 |
| **書き出し先** | Vault 相対パスまたは絶対パス。**参照…**から選択できます。 |
| **表紙を含める** | PDF のときだけ表示。今回の書き出しで `coverInPdf` を上書きします。 |
| **書き出す** | 組版、点検、出力を開始。 |
| **キャンセル** | 実行を中断。 |

既定の出力先は `<出力フォルダ>/<書名>.<形式>` で、初期設定では `_output/書名.pdf` です。フォルダがまだなければ作成されます。絶対パスを指定した場合も親フォルダを作成します。

> ダイアログに表示されたパスが今回の最終的な出力先です。必ず実行前に確認してください。

> **0.1.3 の注意:** `vivlio.yaml` に `output` を書いても、対話式ダイアログの初期値にはまだ反映されません。設定タブの **出力フォルダ**と対象名から作られたパスを、必要に応じてダイアログで変更してください。

## 書き出し処理の流れ

1. 対象ノートを集め、設定三層を解決する。
2. 埋め込み、リンク、記法を変換する。
3. 表紙・扉・目次・奥付を含む本を組み立てる。
4. 画像やフォント等のアセットを準備する。
5. 書き出し前チェックを表示する。
6. PDF は全ページを Vivliostyle で組版して Chromium で印刷する。
7. EPUB は各章を XHTML 化し、CSS、目次、ランドマーク、アセットを梱包する。
8. 必要なら生成ファイルを OS の既定アプリで開く。

## 書き出し前チェック

警告があると一覧が表示されます。**書き出す**で続行、**キャンセル**で原稿へ戻れます。

### 解決できないリンク

本に入っているノートへのリンクか、綴り・別名・見出し名が正しいか確認します。本の外を指すウィキリンクはページ参照を作れないため、文字だけになる場合があります。

### ファイルが見つからない

画像、表紙、前付け・後付けノート、CSS、フォントなどのパスを確認します。

- Vault 相対パスか
- 大文字・小文字、全角・半角が一致しているか
- ファイルを移動・改名していないか
- Vault 外の絶対パスなら **Vault 外のファイルを許可する**がオンか

### 画像の実効 dpi が低い

紙面上の表示幅が大きいほど実効 dpi は下がります。対処は次のいずれかです。

- より高解像度の画像へ差し替える
- `![[画像.png|60%]]` や `![[画像.png|80mm]]` で表示幅を小さくする
- 線画なら SVG を使う
- 用途上問題がなければ続行する
- 警告が不要なら **実効 dpi の警告閾値**を変更する。`0` で無効

### 指定フォントがない

Vivlio はフォントスタック先頭の書体を確認し、見つからなければ実際の代替候補を警告します。

- フォントを OS にインストールする
- `fontFamily` 等のファミリ名を正確に直す
- 複数 OS で使うならフォールバック列を用意する
- 再現性が必要なら `embedFonts` を使う

PDF は Chromium が使用フォントを埋め込みます。EPUB にフォントを同梱するには **EPUB にフォントを埋め込む**を別途オンにし、ライセンスを確認してください。

### 表紙の縦横比が違う

`coverFit: cover` は用紙全面を埋めるため、比率が違う部分を切り抜きます。警告には差と切り抜き量の目安が表示されます。

- 表紙画像を用紙比率に合わせる
- 切り抜きを許容して続行する
- 全体を見せるなら `coverFit: contain` にする

### EPUB に表紙がない

本文の生成はできますが、本棚のサムネイルが空になります。配布用なら `cover` を指定します。`coverPage` のノートだけでは、EPUB のメタデータで表紙として指定される一枚画像を用意できない点に注意してください。

## PDF の性質

- CSS の用紙サイズを優先し、外側の印刷余白は 0 で生成します。
- 背景も印刷します。
- **タグ付き PDF**、**栞**、**メタデータ**を個別に設定できます。
- ノンブル方式が `none` でなければ、前付けと本文に対応した PDF ページラベルを付けます。
- 印刷時は画面用でなく `print` メディアとして組版します。
- 画像の読み込み完了を待ってから印刷します。

## EPUB の性質

- EPUB 3 のリフロー型です。
- 本文は章ごとの XHTML、テーマは一枚の CSS として収録されます。
- 自動目次と同じ見出し階層から `nav.xhtml` を作ります。
- 表紙、扉、本文、奥付などをランドマークとして収録します。
- 縦組みではページ進行方向を右から左にします。
- 紙面専用の固定サイズや目次ページ番号は EPUB 用に外されます。

EPUB リーダーは独自 CSS やユーザー設定で表示を変えることがあります。最低でも縦書き、ルビ、画像、脚注、目次を実際の配布先リーダーで確認してください。

## よくある症状

### プレビューが開かない

1. Markdown ノートがアクティブか確認する。
2. Vivlio が有効か確認する。
3. 固定ポートを使っているなら、ほかのアプリと競合していないか確認する。通常は `0` に戻す。
4. ファイアウォールが `127.0.0.1` の通信を妨げていないか確認する。
5. **Vivlio: 診断ログを書き出す**を実行する。

### `vivlio.yaml`、CSS、EPUB が Obsidian に見えない

**.yaml / .css / .epub をファイルエクスプローラーに表示する**をオンにし、Obsidian を再起動します。別プラグインが拡張子を所有している場合は、そちらのビューが優先されることがあります。

オフのままでもファイルは消えません。OS のファイルマネージャや外部エディタから編集できます。

### 章の順番が違う

次を上から確認します。

1. `vivlio-order` が残っていないか
2. `index.md` 等の目次ノートのリンク順
3. リンクされていないノートが末尾へ追加されていないか
4. 目次ノートがなければファイル名の自然順

### サブフォルダの章が入らない

仕様です。フォルダ本が自動収集するのは直下の `.md` だけです。章を直下へ移すか、目次ノートから明示的にリンクして **このノートを目次として本を組む**コマンドを使います。

### 目次のページ番号が `??`

遅延描画中のプレビューでは、まだ存在しないページを数えられないためです。

- PDF / EPUB へ書き出せば確定します。
- 画面でも必要なら **全ページを最初に描画する**をオンにします。

### 編集中にプレビューが重い

- **プレビューを自動更新する**をオフにし、必要なときだけ再ビルドする
- **更新のデバウンス**を 1000〜2000 ms へ増やす
- **全ページを最初に描画する**をオフにする
- 巨大画像や多数の動的ブロックを減らす
- Dataview 等のクエリを軽くする

### PDF 生成がタイムアウトする

- **PDF 生成のタイムアウト**を 120000 ms より大きくする
- 欠落している外部画像、応答しないリモート CSS を確認する
- 動的ブロックを一時的にオフにする
- 大きすぎる画像を縮小する
- ログレベルを `debug` にして再現し、診断ログを保存する

### プレビューと EPUB の見た目が違う

PDF は固定ページ、EPUB は読者側で再レイアウトするため、改ページ、本文サイズ、画面幅、余白は一致しません。またリーダーがテーマを上書きする場合があります。

固定された紙面が必要なら PDF を使います。EPUB テーマでは、絶対寸法やページを前提とした指定を減らし、`em`、`rem`、`%`、論理プロパティを使います。

### フォントが置き換わる

- CSS に書いた名前と OS 上のファミリ名が一致するか
- フォントスタックの先頭だけでなく後続も適切か
- EPUB なら端末にフォントがあるか、埋め込みが有効か
- 太字・斜体の `weight` / `style` と実ファイルが合うか

### 外部画像が出ない

- **書き出し時に外部画像をダウンロードする**がオンか
- URL が HTTPS でアクセス可能か
- 認証や Cookie が必要な URL ではないか
- 長期保存する本なら画像を Vault 内へ移す

## 診断ログ

コマンド **Vivlio: 診断ログを書き出す**を実行すると、次へログを保存します。

```text
<Vault>/<Obsidian設定フォルダ>/plugins/vivlio/vivlio.log
```

通常の設定フォルダ名なら次です。

```text
<Vault>/.obsidian/plugins/vivlio/vivlio.log
```

書き出しが失敗した場合も、ダイアログにエラー概要とログの保存先が表示されます。問題報告には次を添えると調査しやすくなります。

- Vivlio と Obsidian のバージョン
- OS
- 再現手順
- 最小化した原稿と `vivlio.yaml`
- 自作テーマ
- `vivlio.log`
- 警告またはエラーの全文

## 安全に使うために

- 信頼できないノートでは **dataviewjs / templater を実行する**をオフにする。
- Vault 外パスは必要なときだけ許可する。
- 外部画像とリモート CSS は内容が将来変わるため、確定稿では Vault に保存する。
- フォント、画像、テーマの利用・再配布ライセンスを確認する。
- 入稿前は PDF の用紙寸法、塗り足し、トンボ、フォント、画像解像度を印刷所の仕様と照合する。
