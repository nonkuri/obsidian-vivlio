# 句集・短歌集テーマと原稿記法の検討

調査日: 2026-09-23。`haiku` / `tanka`、`versePerPage`、作品コールアウト、原稿付きサンプルを実装。初版の「見出しの次から作品を組む」処理は撤回し、章の半扉と連作見出しを区別した。現在の仕様は[利用・検証方法](../sample/verse-README.md)を参照。作者欄は当初案のダッシュから `作者：` に変更。長い作品は推定行数に基づいて別ページ群へ分け、警告を出す。天地揃えなどは未実装。

## 再調査と改訂テーマの根拠

前回の実装は改ページと改丁を区別せず、連作の見出しまで意図せず単独ページにしていた。今回の再調査では、次の一般的な組版規則と、出版社・制作会社が示す複数の選択肢を区別した。

| 確認した資料 | 確認できること | 今回の採用方針 |
|---|---|---|
| [W3C 日本語組版処理の要件 §4.1.4](https://www.w3.org/TR/jlreq/#how_to_handle_headings_with_new_recto_page_break_and_new_column) | 改丁は奇数ページ始まり。縦組み・右綴じでは左ページ。左右を問わない改ページや、右ページ始まりも別の選択肢として記述 | 章扉は左ページ始まり。これはすべての歌集の慣例という主張ではなく、本テーマの既定値 |
| [JAGAT 中とびらの組版処理](https://www.jagat.or.jp/kumihan_nakatobira) | 中扉は原則裏白。裏から本文を始めるものは半扉。扉には柱を置かず、現在はノンブルも一般に省く | 裏白を増やさない半扉を採用し、柱・ノンブルを隠す。ページ数には算入 |
| [サンプリント 四六判 句集・歌集の組見本](https://www.sunprint-books.jp/803936798) | 掲載数に決まりはなく、2・3句が多いという制作会社の説明。1句・5句・注付きの例もある | 1・2・3作品の比較を維持。2作品を既定値とし、標準規格とは呼ばない |
| [ちょこっと出版 テンプレート](https://chokottopub.com/dl) | 歌集・句集の2行・3行などの版式と、複数の章扉デザインを用意 | 一つの正解に固定しない。今回の章題は中央・4字下げ、本文はアタマ揃えというデザイン上の選択 |

一章一ノートの `#` は半扉、`##` 以下は作品に続く見出しとする。直後が作品の場合は同じページに組み、見出し用の幅を確保する。書名の `#` を持つ一冊一ノートなら、本文に残る `##` が章、`###` が連作となる。詞書は見出しとは別で、その作品に付随させる。

半扉は版面の左右中央・天から本文4字分下げ、明朝・通常ウェイト・本文の1.4倍。連作見出しは本文と同じ大きさで2字下げ。これらの寸法は資料から実測した「業界標準」ではなく、今回の組見本として選んだ値である。通常本文の柱・ノンブル、ルビ、意図した空白と改行、長い作品の全量保持を維持する。

## 推奨方針

作品の境界、前書き・詞書、本文、作者を原稿で明示し、その構造に対して組版を適用する。**共通の作品記法＋句集・歌集のプリセット＋原稿付き組見本**を一つの提供単位にする。

最初は四六判・縦組み・明朝体・モノクロで、1頁2作品を比較の基準にする。これは市場の唯一の標準という意味ではなく、余白と収録量の比較を始めるための開発上の選択。1頁3作品と1作品も同じ原稿で比較する。

## テーマとして必要な区別

- **作品数／頁**：1・2・3作品など。小説の段組み設定とは別。
- **行数／作品**：一行書き、作者が指定した複数行書き、版面による折り返しを区別。
- **文字の揃え**：まずアタマ揃え。天地揃えは別の検証対象とする。
- **作品の付属情報**：短い前書き・詞書、作者、注釈を本文と区別。
- **まとまり**：部・章・連作は見出しとして扱う。一作品ごとに見出しを必須にしない。
- **散文**：序文・あとがき・解説には通常の段落組版を適用する。

俳句の17音・短歌の31音は、印字する17字・31字と同じではない。固定字数による分割や、五七五／五七五七七の自動改行は行わない。原稿の空白・旧字・ルビも作者の表記として扱う。

文字サイズや作品間隔だけのCSSでは、詞書と作品を一緒に送ること、長い作品だけ別扱いにすること、散文を作品数に数えないことを安定して実現できない。構造の定義を先に行う。

## Markdown記法の比較

| 案 | 良い点 | 課題 | 判断 |
|---|---|---|---|
| 空行で区切った段落を一作品とする | 入力が最短 | 詞書・散文との区別がつかない | 既存原稿の取り込み候補。標準にはしない |
| 箇条書きの1項目を一作品とする | Markdownとして読みやすい | 付属情報の役割を追加定義する必要がある | 代替候補 |
| 専用コールアウト | Obsidianで作品の境界が見える。既存の変換処理を利用できる | 作品が多いと記号が増える。役割の解釈には追加処理が必要 | 第一試作候補 |
| `:::verse` などの独自コンテナ | 構造を明示しやすい | この用途の現行対応を確認できず、Obsidian上の表示も検討が必要 | 初版では増やさない |
| 生HTML | 構造を細かく指定できる | 日常の推敲には負担が大きい | 上級者用の逃げ道 |

### 推奨する試作記法（未実装）

以下の作品は記法説明用の創作例。一つの章ノート内で使う想定。

```markdown
# 春の川

## 帰り道

> [!haiku]
> 春の川橋の向こうに母の傘

> [!tanka] 故郷を訪ねて
> 改札を抜ければ風の匂いして遠くの山は昔のままで
>
> — 山田花子
```

提案する意味は次のとおり。

- `[!haiku]` / `[!tanka]` 一つにつき一作品。種類は作品構造として保持する。
- マーカー行の任意のタイトルを短い前書き・詞書にする。空なら何も印刷しない。
- 本文段落を作品とする。音数の検査・改変はしない。
- 最後の独立段落の `— ` を作者欄とする案。本文と衝突する場合のエスケープ規則は仕様化時に決める。個人集では省略できる。
- 通常改行は執筆時の折り返し、明示的なMarkdownの強制改行を作者指定の改行とする案。変換結果の検証後に確定する。
- 複数段落の詞書、長い自注、連作全体への詞書は次の段階で構文を決める。段落位置から曖昧に推測しない。

この記法は最終決定ではない。通常の無題作品を多数書く負担と、詞書・作者を付けるときの分かりやすさを、実際のノート編集で比較する。テンプレート挿入も検討する。

### 原稿と本設定の分担

原稿には作品・順序・見出し・詞書・作者・意図した改行を書く。本設定やテーマには判型・掲載密度・字体・文字サイズ・配置を書く。2作品／頁から3作品／頁に変更するだけなら原稿は編集不要にする。

一作品一ノートも将来の選択肢だが、初期の説明は一章・一連作一ノートとする。現行ではノートが章ドキュメントになるため、一作品一ノートをそのまま章として列挙すると複数作品／頁の設計と衝突しうる。埋め込みを利用する場合も、章見出し・メタデータの取り込み方を検証する。

## 現行実装との接点

- [コールアウト変換](../src/build/hast/obsidian.ts)は任意の種類を `aside.callout` に変換する。現状では無題でも種類名をタイトルとして補う。作品用には空タイトルを出さない処理が必要。
- 現在は詞書・本文・作者という役割を解析していない。専用変換で意味を持つ要素へ整理し、通常のコールアウト装飾から独立させる案を推奨する。
- [変換パイプライン](../src/build/vfm.ts)は空行処理、コールアウト変換、字下げ処理などを持つ。作品内では散文用の字下げと連続空行処理が表現を変えないようにする。CSSで消すだけでなく、入力の全角空白が失われないか確認する。
- [原稿マニュアル](../manual/05-writing-and-structure.md)に既存のルビ・改ページ記法がある。専用の別記号を増やさず再利用する。
- EPUBはリフロー型。作品の順序・構造・明示改行を保持し、PDF用の固定寸法や作品数／頁は外す方針とする。

## 試作する紙面と検証条件

初回は共通の作品構造を作り、句集2句／頁、歌集2首／頁、比較用3作品／頁・1作品／頁を小さな原稿で試す。公開するテーマ名や設定キーは、この比較の後で確定する。

同じサンプルに、通常作品、ルビ付き、長い作品、明示改行、詞書、作者付き、連作見出し、序文・あとがきを入れる。章末が1作品だけになる例も含める。

受け入れ条件:

1. 作品本文と短い詞書・作者が頁をまたいで分離しない。
2. 2／3作品の指定で、通常頁の配置位置が安定する。章末の不足分を引き延ばさず、残りの位置を空ける。
3. 章・連作見出しだけが頁末に残らない。章扉にするか作品と同頁にするかの規則を固定する。
4. 指定枠を超える場合、無断の縮小・切り捨てをしない。掲載数を減らすなどの扱いを明示し、1頁にも収まらない例を検出する。
5. 作品の全角空白・ルビ・明示改行が保持される。短歌を自動で上句・下句に分けない。
6. 強制改ページを入れた箇所では作者のページ構成を優先する。
7. EPUBで固定配置を解除しても詞書→本文→作者の順で読める。

`break-inside: avoid` だけで全条件を満たすとは考えない。固定スロットと長い付属情報、頁分割の挙動はVivliostyleで試作して確認する。テーマCSSだけで難しい部分はビルド処理の責務に分ける。

最初の提供物はテーマ単体でなく、**短い原稿、設定、組見本PDF、EPUB、書き方の説明**を揃える。高密度の5句組、天地揃え、多行書きの複雑な字下げ、注釈中心の合同集は、標準構成の検証後に拡張する。
