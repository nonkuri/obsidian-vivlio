# Vivlio

[English](README.md) | **日本語**

Obsidian のノートを [Vivliostyle](https://vivliostyle.org/) で組版します。CSS 組版（paged media）による縦書き、ルビ、傍点に対応し、プレビューを見ながら PDF と EPUB に書き出せます。

デスクトップ専用です（`isDesktopOnly: true`）。初回起動時に何もダウンロードしません。組版エンジンはプラグインに同梱されていて、PDF は Obsidian がすでに動かしている Chromium が刷ります。

仕様は [docs/SPEC.md](docs/SPEC.md) にあります。設定タブから `vivlio.yaml`、原稿の書き方、テーマの自作、トラブルシューティングまでを扱った詳細マニュアルを [manual/](manual/00_vivlio_plugin_manual.md) にまとめています。

![左に Obsidian のノート、右に Vivlio のプレビュー。エディタに素のまま置かれた vivlio-* フロントマターと ｜遠雷《えんらい》・《《…》》 の記法が、隣のペインでは縦組みの本文になっている。](docs/images/obsidian.png)

*左がノート、右がページ。プレビューは PDF と同じエンジン、同じスタイルシートを使います。*

プレビューだけでできないことが 1 つあります。目次のページ番号は、全ページが組まれるまで `??` と表示されます。番号は `target-counter` が数えるもので、まだ組まれていないページには数える対象がないためです。書き出しは常に本全体を組むので、PDF と EPUB は正しい番号になります。画面上でも実際の番号を見たい場合は、設定の **全ページを最初に描画する** を有効にしてください。プレビューの表示までは遅くなりますが、最初から正しい番号が出ます。

## できること

| | |
|---|---|
| **プレビュー** | 実際のページの組み上がりを表示します。PDF と同じエンジン・同じスタイルシートです。縦書き、ぶら下げ組、和欧間のアキまで含まれます。いずれも Obsidian 標準の PDF 書き出しでは得られません。 |
| **1 つのノートでも、まとめてでも** | ノート 1 つがそのまま 1 冊になります。フォルダを指定すればその直下のノートが、目次ノートを指定すればそれが `[[リンク]]` で並べたノートが、1 冊になります。 |
| **Obsidian の記法** | 埋め込み、ウィキリンク、コールアウト、タスクリスト、タグ、ハイライト。加えて青空文庫・カクヨム式のルビ、傍点、縦中横。 |
| **PDF** | タグ付き、検索可能。しおり、メタデータ、`i, ii, iii, 1, 2 …` のページラベル付き。フォントは Chromium が埋め込んでサブセット化するので、他の環境でも印刷できます。 |
| **EPUB 3** | リフロー型。テーマの CSS、表紙、ランドマークを含みます。 |
| **書き出し前の点検** | 300 dpi を下回る画像、この PC にないフォント、ページと縦横比の合わない表紙を報告します。 |

## インストール

**Obsidian から。** 設定 → コミュニティプラグイン → 閲覧 で *Vivlio* を検索し、インストールして有効化します。

**手動で。** [リリース](https://github.com/nonkuri/obsidian-vivlio/releases) から `main.js`、`manifest.json`、`styles.css` を取得し、`VaultFolder/.obsidian/plugins/vivlio/` に置きます。Obsidian を再読み込みして、コミュニティプラグインから有効化してください。

デスクトップ版の Obsidian 1.8.7 以降が必要です。PDF は Obsidian がすでに動かしている Chromium で刷るため、モバイル版はありません。

## プレビューを表示する

方法は三つ、手近なものをどうぞ。

- **リボン** — 左のリボンにある本のアイコンで、開いているノートを組版します。
- **コマンドパレット** — `Vivlio: プレビューを開く` も同じ動きです。
- **ファイルエクスプローラの右クリックメニュー** — Markdown ノートを右クリック
  すると **Vivlio: プレビュー**。*フォルダ*を右クリックすると **Vivlio: 本と
  してプレビュー**（フォルダ内のすべての `.md` を章の順序で）と、その隣に
  **Vivlio: 本として書き出す** が出ます。

ペインは右側に開き、上部にツールバーが載ります。**再組版**、テーマの選択、
そして表示中のものをそのまま書き出しダイアログに渡す **PDF** / **EPUB** の
ボタンです。ノートを編集すれば組み直しますが、設定タブの
**プレビューを自動更新する** をオフにすれば止まります。その場合はツールバーの
ボタンか `Vivlio: 組版結果を再読み込み` で組み直してください。

## コマンド

| コマンド | 内容 |
|---|---|
| `Vivlio: プレビューを開く` | アクティブなノートをサイドペインで組版 |
| `Vivlio: PDF に書き出す` / `EPUB に書き出す` | 書き出しダイアログ、点検、そしてファイル |
| `Vivlio: このフォルダを本として書き出す` | フォルダ内のすべての `.md` を順に |
| `Vivlio: このノートを目次として本を組む` | ノートの `[[リンク]]` が本文の並び順になる |
| `Vivlio: 本の設定を作成` | `vivlio.yaml` を書くウィザード |
| `Vivlio: このノートに設定を追加` | フラットな `vivlio-*` フロントマターを挿入 |
| `Vivlio: 設定リファレンスを書き出す` | すべてのキーを既定値とコメント付きで |

ファイルエクスプローラの右クリックメニューからもプレビューと書き出しができます
（「プレビューを表示する」を参照）。

表示言語は既定で Obsidian の設定に追随します（設定タブで固定もできます）。

## 本の設定

3 つの層があり、下の層が上の層を上書きします。

1. **設定タブ** — Vault 全体の既定値。
2. 本の隣に置く **`vivlio.yaml`** — 本の設定を書く本来の場所です。入れ子とコメントが使えます。
3. **ノートのフロントマター** — フラットな `vivlio-*` キーのみ。Obsidian のプロパティエディタで編集できるようにするためです（入れ子の YAML は編集できません）。

```yaml
# vivlio.yaml
title: 吾輩は猫である
author: 夏目漱石

theme: novel              # novel、または Vault 内の CSS のパス（「テーマを自作する」参照）
writingMode: vertical-rl
size: 文庫
charsPerLine: 39
linesPerPage: 15
footnote: gcpm            # ページ下部に

cover: 装丁/表紙.png
sections:
  titlePage: auto
  toc: auto
  preface: まえがき.md
  colophon: auto
pageNumbering: roman-then-arabic
startPage: 1             # 本文のノンブルを何番から始めるか
output: 原稿/出力/猫.pdf
```

```yaml
---
title: 吾輩は猫である
vivlio-theme: bunko
vivlio-size: 文庫
---
```

ノート自身の `title` も読むので、1 つのノートを単独で書き出すぶんには `vivlio-title` は要りません。書名とノートのタイトルを分けたいときに `vivlio-title` を書きます（そちらが優先されます）。`Vivlio: このノートに設定を追加` が挿入するのはこの形です。このコマンドが提示するキーはすべて `vivlio-` を付けた名前になるためです。

`Vivlio: 設定リファレンスを書き出す` を実行すると、すべてのキーを既定値とコメント付きで列挙した `vivlio.yaml` が得られます。

## 章の順序

1. 目次ノート（`index.md`、フォルダ名と同じ名前のノート、または `vivlio-toc: true` を持つノート）があれば、その `[[リンク]]` の並び順。
2. なければファイル名の自然順。`2.md` は `10.md` より前に来ます。
3. `vivlio-order: 3` はどちらの場合も位置を固定します。

目次ノート自身は、`includeToc: true` としない限り本には含まれません。

`vivlio-order` と `vivlio-toc` は本ではなくノートに属する設定なので、`vivlio.yaml` には書けず、設定リファレンスにも出てきません。`Vivlio: このノートに設定を追加` が両方を提示します。

## 記法

| 書くと | こうなる |
|---|---|
| `《《テキスト》》` | 傍点（カクヨム式） |
| `漢字《かんじ》` | 直前の漢字の連なりにルビ。原稿がほぼこの形で書く省略形（`々〆〇ヵヶ` も漢字として扱います） |
| `｜任意《よみ》` | 任意の親文字にルビ。`｜` が親文字の始まりを示します（半角の `\|` も可） |
| `{漢字\|かんじ}` | ルビ（VFM 本来の記法） |
| `^^1/2^^` | 縦中横。4 文字まで |
| 縦書き中の 1〜2 桁の半角数字 | 自動で正立。2 桁は 1 em に組み合わせ、1 桁は横倒しにせず立てます。前後に数字・英字・`. , : % -` が隣接しないときだけ |
| `==ハイライト==` | 傍点、太字、`<mark>`、または素のテキスト — 選べます |
| `［＃改ページ］` | 強制改ページ。青空文庫の注記と同じ書き方です |
| 3 行以上の連続した空行 | 紙面の空き。`n` 行の空行が `n - 2` 行アキになります |
| 行頭の全角スペース | その段落を字下げする指示として読み、文字自体は取り除きます |
| `> [!任意]` | 囲み罫のコールアウト。種別は何でもよく、`callout-<種別>` として残るのでテーマで差をつけられます |
| `![[fig.png\|300]]` | 幅を指定して画像を配置。`300`、`300x200`、`60%`、`80mm`、`300px` |
| `![キャプション](fig.png)` | `<figure>` になり、キャプションが図の下に出ます。`![[…]]` は幅、こちらはキャプション |
| `![[ノート]]`、`![[ノート#見出し]]` | そのノートの本文をその場に組み込みます（深さ 3 まで。循環は拒否） |
| `[[ノート]]`、`[[ノート\|表示名]]` | 本に含まれるノートならリンク、含まれなければプレーンテキスト |
| `- [ ]` | ☐ / ☑。フォーム部品ではなく文字として描画 |
| `mermaid` / `dataview` のコードブロック | Obsidian のレンダラで描画し、図として配置 |
| `#tag`、`%%comment%%`、`^block-id` | 削除 |

どの段階も設定タブで個別に無効化できます。またいずれもコードブロックの中には手を出しません。変換は Markdown のソースではなく、文書ツリーに対して行われるからです。

## テーマを自作する

`theme:` には Vault 内のスタイルシートのパスも書けます。そのスタイルシートは、同梱テーマを出発点にできます。

```css
/* 装丁/私の本.css */
@import url("vivlio:novel");

:root {
  --vs-novel--chars-per-line: 42;
  --vs-novel--lines-per-page: 17;
  --vs-novel--boten-font-size: 0.32rem;
  --vs-novel--secondary-ink: #4a4a4a;
}

.callout-warning { border-color: #b00; }
```

```yaml
# vivlio.yaml
theme: 装丁/私の本.css
```

`vivlio:novel` はこのプラグインのために作られたテーマで、版面の設計・ノンブルの位置・見出しの空きはすべてこれを基準に調整されています。CC0 の Vivliostyle テーマである `vivlio:base`、`vivlio:bunko`、`vivlio:techbook`、`vivlio:academic` も解決されますが、テーマの選択欄に出るのは `novel` だけです。ほかはこのプラグインのノンブルや見出しと突き合わせた確認がまだ済んでいないためです。

これ以外の `@import` は通常の取り込みで、書いたファイルからの相対パスとして Vault から読まれます。各ファイルは一度だけ辿るので、import が輪になっていても問題ありません。使う前に 1 枚のスタイルシートに畳まれるので、プレビューと EPUB がまったく同じ内容を読みます。

書くときに知っておくとよいクラス: `.boten`、`.tcy`、`.callout` と `.callout-<種別>`、`.task-list`、`.vivlio-page-break`、`.vivlio-blank-lines`、`.vivlio-no-indent`、`.vivlio-rendered`。

## ビルド

```bash
npm install
npm run build
```

リリースが配るのは `main.js`、`manifest.json`、`styles.css` の 3 つです。ビルド済みの Vivliostyle ビューアと 4 つの CC0 テーマはバンドルに埋め込まれているので、ほかにコピーするものはありません。

```bash
npm test
```

テストは実際の変換パイプライン、設定の各層、ローカルサーバを、Obsidian の外で、アプリ API の小さなスタブに対して動かします。

## リリース

`npm version patch`（または `minor` / `major`）が、新しい番号を `package.json`、`manifest.json`、`versions.json` に一度に書き込みます。そこで作られたタグを push すれば、それがリリースのすべてです。ワークフローがバンドルをビルドし、タグとマニフェストが一致することを確かめ、3 つのファイルを個別のアセットとしてアップロードします。これが Obsidian のインストーラが期待する形です。

```bash
npm version patch
git push --follow-tags
```

## しくみ

```
ノート ──▶ VFM（＋このプラグインのフック）──▶ HTML + 生成された CSS
                                                │
                                    127.0.0.1（トークンで限定）
                                                │
                            ┌───────────────────┴───────────────────┐
                            ▼                                       ▼
                iframe + Vivliostyle ビューア        隠し webview → printToPDF
                        （プレビュー）                 → pdf-lib（しおり、
                                                          メタデータ、ページラベル）
```

Vivliostyle は文書とその素材を XHR で取得するため `file://` が使えません。そこでプラグインは、プレビューか書き出しが開いている間だけ、ビルド結果をループバックで配信します。このサーバは `127.0.0.1` にのみバインドし、すべての URL にセッションごとのトークンを要求し、`Host` ヘッダを検査し、GET と HEAD にしか答えず、CORS ヘッダを返さず、Vault の外のパスを拒否します（明示的に設定されたフォントの場所だけが例外です）。
